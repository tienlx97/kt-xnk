## React Docs-style MDX navigation (2026-08-13)

Created and published branch `feat/mdx-react-style-sidebar` to reshape the
site navigation using the MIT-licensed implementation in
`reactjs/react.dev/src/components/Layout` as the behavioral and dimensional
reference, while retaining KT-XNK theme tokens, logo, routes, and content.
The finished navigation uses a custom semantic top nav instead of Astryx
`TopNav`: 64px desktop header, logo at left, route pills and user menu at
right, and a hamburger below 1024px. The custom sidebar is 320px wide and
sticky on desktop, with a 320px mobile drawer. It does not use Astryx
`SideNav`, `SideNavItem`, or `SideNavSection`.

Typography was split between document content and navigation UI to match the
React Docs hierarchy: article body remains 17px; top nav is 15px with normal
weight and a 500 active state; top-level sidebar items are 15px bold; nested
sidebar links are 13px/400; table-of-contents heading and links are 13px, with
only the active TOC item at weight 700. The Astryx `List` implementation was
removed from the TOC because it inherited an oversized type scale.

Sidebar visibility and content are route-contextual. The AppShell receives a
sidebar and mobile drawer only for `/tutorial`, `/tutorial/*`, `/docs`, and
`/docs/*`; home, design-system, and other routes use the full-width frame with
no empty sidebar column or navigation hamburger. Tutorial routes show only
the Tutorial overview and Tutorial entries; Docs routes show only the Docs
overview and Docs entries.

Navigation data now follows the React Docs JSON registry pattern rather than
being constructed directly from MDX metadata. The project uses
`src/sidebarTutorial.json` and `src/sidebarPost.json`, with records shaped by
`title`, `path`, `routes`, `hasSectionHeader`, and `sectionHeader`.
`sidebarBlog.json` was renamed to `sidebarPost.json`; the user-facing Blog
domain and `/blog` routes were replaced by internal company documentation at
`/docs`, and `src/features/blog` became `src/features/docs`.

Two renderer bugs were fixed while adopting the JSON schema. Top-level rows
use stable Fragment keys derived from path, section header, title, and an
index fallback, eliminating React's unique-key warning. A record with
`hasSectionHeader: false` and no `path` is skipped rather than falling through
to an empty link row.

Parent sidebar rows follow React Docs navigation semantics: the Docs parent is
a real link to `/docs`, not an expand/collapse button. Child visibility is
derived from the current route, so `/docs/[slug]` keeps the group open and
clicking Docs returns to the overview instead of collapsing the group. The
chevron reflects open state only; mobile parent navigation also closes the
drawer.

All navigation changes passed formatting, lint, typecheck, unit tests,
production build, and the full `./harness/verify.sh` gate. The main published
commits on `feat/mdx-react-style-sidebar` were:

- `912feaa feat(mdx-sidebar-navigation): match React Docs layout`
- `1b68160 chore: add workspace configuration and font assets`
- `f4473ad feat(docs): replace blog with company documentation`
- `9cdc793 fix(sidebar): keep parent routes navigable`

The first publish intentionally excluded local `.vscode/settings.json`,
`.codex/`, and two TTF files; the user then explicitly requested that they be
included, and they were committed separately in `1b68160`.

## Project-local Astryx MCP for Codex (2026-08-13)

Astryx exposes an MCP server at `https://astryx.atmeta.com/mcp`. The existing
project `.mcp.json` is retained because OpenCode and Claude use it. Codex does
not read that file, so project-local Codex configuration was added separately
at `.codex/config.toml`:

```toml
[mcp_servers.xds]
url = "https://astryx.atmeta.com/mcp"
```

`codex mcp list` confirmed `xds` as enabled. A new Codex session opened from
the trusted project directory is required to load the newly configured MCP
tools. The reported `Auth: Unsupported` state refers to unsupported OAuth for
that endpoint, not to the server being disabled.
